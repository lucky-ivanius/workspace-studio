# Foundation

This document describes the setup that is in place and the contracts to work
against. For the brief, see [REQUIREMENTS.md](./REQUIREMENTS.md).

## What runs today

Open the app and you can add a desk, add a chair and accessories, drag anything
to a new tile, and watch the checkout summary update with live monis.rent
prices. That loop exists to prove the foundation, not to be the final product.

## Stack

| Concern         | Choice                                          |
| --------------- | ----------------------------------------------- |
| Framework       | Next.js 16 (App Router, Turbopack), React 19    |
| Canvas          | pixi.js 8, driven imperatively from a store     |
| State           | zustand 5                                       |
| UI chrome       | Tailwind 4, shadcn (base-luma), lucide icons    |
| Lint and format | Biome                                           |
| Tests           | `node:test` via `tsx`, Playwright for the browser |

Pixi is used directly rather than through `@pixi/react`. The scene needs custom
hit-testing, grid snapping, and depth sorting, which are clearer as imperative
code than as a reconciled tree. React owns every pixel outside the canvas.

## Layout

```
src/features/studio/
  model/        Domain. Pure, no Pixi, no React. Fully unit tested.
    grid.ts       Isometric maths: tile <-> screen, footprints, depth
    types.ts      AssetSpec, Product, PlacedItem
    assets.ts     Asset registry: the single source of truth for art sizes
    catalog.ts    Typed view over catalog.json
    catalog.json  Generated by `pnpm catalog:sync`
    placement.ts  Placement rules, surfaces, draw order
  state/        zustand store and the checkout summary selector
  engine/       Pixi: asset loading and the scene
  components/   React: canvas mount, catalog panel, summary panel

e2e/            Playwright browser tests
scripts/
  sync-catalog.mjs                 Pulls products from monis.rent
  generate-placeholder-assets.mjs  Draws stand-in art at exact sizes
```

The dependency direction is one-way: `components -> state -> model` and
`engine -> model`. Nothing in `model/` imports React or Pixi, which is why it
can be tested with plain Node.

## The grid

The room is a 10x10 isometric grid of 128x64 px tiles. One tile is **40 cm** of
floor, so a 4x2 desk is 160x80 cm — the size monis.rent actually rents.

Tile `(0, 0)` sits at world origin. Moving one tile along `x` goes right and
down; one tile along `y` goes left and down.

```
screen.x = (x - y) * 64
screen.y = (x + y) * 32
```

Items are positioned by the **centre of their footprint**, lifted by their
elevation. Depth is the footprint's front corner, `x + w + y + d`, so larger
means nearer the camera. Two items on the same `x + y` diagonal are the same
distance away and their order is arbitrary.

### Draw order

`zIndexOf` in `placement.ts` keys draw order on the support hierarchy first and
isometric depth second. An item resting on a desk is keyed off that desk, so it
always draws over it, while a floor item one diagonal nearer still draws over
both. Getting this wrong is subtle, so it is covered by tests.

### Surfaces

An item sits on the `floor`, or on the `desk` surface of a specific host desk.
Desks declare `surfaceHeightCm`; anything placed on one is raised by that
height and constrained to the desk's tiles. Removing a desk removes everything
on it.

## The asset contract

This is the important part. Every PNG has exactly one correct size, derived
from its grid footprint, so art and placement cannot drift apart.

A registry entry declares two things about shape:

- `footprint: { w, d }` — tiles occupied, at 40 cm per tile
- `heightCm` — how tall the real object is

Everything else is computed:

```
span        = w + d
designWidth  = span * 64
baseHeight   = span * 32           (the footprint rhombus)
standHeight  = round(heightCm * 1.6)
designHeight = baseHeight + standHeight

fileWidth  = designWidth  * 2      (art is authored at 2x)
fileHeight = designHeight * 2

anchor = (designWidth / 2, designHeight - baseHeight / 2)
```

### Drawing an asset

1. Create a canvas at the file size the registry reports.
2. The footprint rhombus fills the **bottom `baseHeight * 2` px**, edge to edge
   horizontally. That is the floor the object stands on.
3. Draw the object standing on that rhombus, growing upward. It may not exceed
   the canvas top.
4. Leave the rest transparent.

Worked example, `monitor-27-4k` (footprint 2x1, 50 cm tall):

```
span = 3  ->  design 192 x 176  ->  file 384 x 352
footprint rhombus occupies the bottom 192 px of the file
anchor at design (96, 128)
```

The placeholder generator draws this rhombus with a white anchor tick, so you
can open any placeholder to see exactly where the contract puts things.

### Adding or changing an asset

1. Add an `isoAsset({ ... })` entry to `SPECS` in `model/assets.ts`.
2. Run `pnpm assets:placeholders` to draw a stand-in. Existing files are never
   overwritten; pass `--force` to redraw them.
3. Replace the file with real art at the same dimensions.
4. Map a product to the asset (see below).

In development, the app also checks every loaded texture against its declared
size and logs a console error naming the file and both sizes if they disagree.

## Tests

Two layers, each covering what it is good at.

**`pnpm test`** runs `node:test` through `tsx` against `src/**/*.test.ts`. These
are the grid maths, the placement rules, draw order, the store, and pricing. No
browser, no Pixi, so they run in well under a second.

One of them is worth calling out: `model/assets.test.ts` reads the IHDR header of
every PNG on disk and asserts it matches the registry. Draw a file at the wrong
size and `pnpm test` tells you which file and what size it should be.

**`pnpm test:e2e`** runs Playwright against Chromium. It builds the app and
serves it, so the run always reflects current code. These tests cover the wiring
the unit tests cannot: that WebGL actually boots, that catalog clicks place items
on the canvas, that a pointer drag moves an item to a new tile, and that the
checkout arithmetic shown on screen adds up.

Every e2e test asserts no console errors or uncaught exceptions occurred, so a
failed texture load or a Pixi error fails the suite rather than going unnoticed.

The drag test does not hardcode screen positions. It scans the canvas for the
`grab` cursor Pixi sets on hover to find a sprite, drags it, then checks the
cursor is `grab` at the drop point and no longer `grab` where it started. That
exercises real hit-testing and stays correct if the camera changes.

### CI

`.github/workflows/ci.yml` runs on every push to `main` and every pull request,
as two parallel jobs:

- **check** — `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`
- **e2e** — `pnpm test:e2e` on Chromium, with the browser cached by Playwright
  version. The Playwright report and traces upload as an artifact on failure.

The Node version comes from `.node-version`, which local tooling (nvm, fnm,
Volta) reads too, so there is one place to change it. The pnpm version comes
from `packageManager` in `package.json`.

A run of the suite against a new commit always rebuilds, so a green tick never
reflects stale output.

## Product data

monis.rent has no public API, so `pnpm catalog:sync` reads the product payload
each product page embeds and writes `model/catalog.json`. That file is
committed, so nothing scrapes at build or request time.

Each entry carries the real name, description, weekly rate, long-stay weekly
rate, monthly rate, discount, security deposit, and the source URL. The slug is
kept so live data can be joined in later.

To add a product: add a line to `SOURCES` in `scripts/sync-catalog.mjs` with
its slug, the `assetId` it maps to, and a category, then re-run the sync.

Items in `DECOR` (plant, rug) are staging only. They have no price and are
excluded from checkout.

### Pricing

`pricePerWeek` applies under one month; `longStayPricePerWeek` applies beyond
it, which is the "From $X/week" figure the storefront shows. `weeklyRate` picks
the tier and `summarize` builds the checkout lines.

## Commands

```bash
pnpm dev                  # dev server
pnpm test                 # unit tests: grid, placement, store, pricing, assets
pnpm test:e2e             # Playwright browser tests
pnpm typecheck            # tsc --noEmit
pnpm lint                 # biome check
pnpm build                # production build

pnpm catalog:sync         # refresh product data from monis.rent
pnpm assets:placeholders  # draw missing placeholder art
```

Playwright needs its browser once per machine:

```bash
pnpm exec playwright install chromium
```

Useful flags: `pnpm test:e2e --ui` for the interactive runner,
`pnpm test:e2e --headed` to watch it drive a real window, and
`pnpm test:e2e --grep "dragging"` to run one test.
